## 하나의 화면에서, 여러 시간이 함께 흐릅니다

DOMADO PROJECT에는 입장 로고, 브랜드 인트로, 메인 공간, 음악, 소개 카드와 연락 연출이 있습니다.<br>
각각의 애니메이션을 만드는 것만큼, **언제 시작하고 멈추며 다음 화면에 무엇을 넘겨줄지**가 중요했습니다.<br>
`main.js`는 이 상태를 연결하고, 각 모듈은 자신의 입력·모션·자원 정리를 맡습니다.<br><br>

| 원본 모듈 | 책임과 연결 |
|---|---|
| `main.js` | 진입 완료, 프로젝트·채널 선택, 두 dialog, 초점 복원, 3D 중지·재개 연결 |
| `entry-scene.js` | 금속 로고, 직접 회전·관성, 입장 장면의 WebGL 자원 해제 |
| `brand-intro.js` | SVG 인트로와 제목 모션, 탭 전환, 정적 대체, 종료·실패 처리 |
| `universe.js` | 카메라·조명·렌더링, OrbitControls, 선택·라벨, 휠·핀치·키보드 |
| `scene-math.js` | 재현 가능한 배치, 거리·회전·감속·모션 계산 |
| `models.js` · `air-model.js` | 로고·기기·장식의 절차적 형상과 재질, 종이비행기와 날개 |
| `icon-motion.js` | 복제본별 부품 반응, 필요한 자원의 분리와 정리 |
| `space-background.js` | Points 배경 별과 셰이더 성운 |
| `soundtrack.js` | 음원 준비, 음악 연결, 음소거·탭 전환·늦은 응답 처리 |
| `project-navigation.js` · `logo-menu.js` | 소개 탭의 가로 탐색, 로고 메뉴 위치와 초점 |
| `contact.js` · `contact-feedback.js` · `contact-flight.js` | 입력·요청 상태, 상태 안내, 성공 이후의 비행 연출 |

위 이름은 비공개 원본의 구조를 설명합니다. 이 공개 저장소에 애플리케이션 코드가 포함되어 있지는 않습니다.<br>

## 1. 진입 화면과 메인 공간의 수명을 나누기

첫 HTML에는 입장 화면과 문구가 있습니다.<br>
JavaScript가 준비되면 Explore가 활성화되고, 사용자가 누른 뒤 음악을 준비합니다.<br>
음원 준비가 실패하거나 3초를 넘겨도 무음으로 다음 화면에 들어갈 수 있습니다.<br><br>

일반 모션에서는 입장 화면의 0.28초 페이드 뒤 브랜드 SVG를 재생합니다.<br>
SVG의 5.8초 모션이 끝나고 0.6초 페이드로 메인 화면을 보여줍니다.<br>
탭이 숨겨지면 진행을 멈추고, 돌아왔을 때 남은 구간을 이어갑니다.<br>
모션 감소·고대비 설정에서는 같은 브랜드를 정적으로 6.4초 보여줍니다.<br><br>

입장 로고는 별도의 renderer를 사용합니다.<br>
화면이 끝나면 geometry·material·환경 맵과 renderer를 정리하고 해당 WebGL context를 해제합니다.<br>
메인 `universe`는 입장 중에도 초기화되지만, 진입이 끝날 때까지 탐색이 중지된 상태로 기다립니다.<br>
따라서 전체 3D 초기화를 Explore 이후로 미룬 구조로 설명하지 않습니다.<br><br>

메인 진입에서는 카메라가 약 19.08의 거리에서 기본 거리 12.6으로 이동합니다.<br>
아이콘 자체가 중앙에서 방사형으로 폭발하는 구현은 아닙니다.<br>
README Hero는 이 진입 인상을 실제 모델 이미지의 확산 모션으로 재구성했습니다.<br>

## 2. 조작을 하나의 기준으로 맞추기

카메라는 반경 36인 공간의 중심을 기준으로 회전합니다.<br>
OrbitControls의 회전·감쇠를 사용하고 패닝은 끕니다.<br>
좌우는 계속 회전할 수 있으며, 상하는 ±60°로 제한합니다.<br><br>

| 입력 | 처리 |
|---|---|
| 마우스·터치 드래그 | 카메라 회전. 놓은 뒤 관성이 잦아들고 자동 회전으로 연결 |
| 휠 | 픽셀·줄·페이지 단위를 반영하고 목표 거리로 부드럽게 이동 |
| Ctrl/⌘ + 휠 | 브라우저 기본 동작 유지 |
| 핀치 | 두 손가락 거리로 줌. 종료 시 선택을 방지하고 남은 손가락으로 드래그 연결 |
| 방향키 · `+` · `−` | 회전과 거리 조절. 휠 입력 이후의 현재 거리에서 계속 계산 |
| `Home` | 시점과 거리 복귀, 이전 관성 정리 |
| `Space` | 캔버스에 초점이 있을 때 자동 움직임 일시정지·재개 |

거리는 로그 공간에서 보간해 가까운 곳과 먼 곳의 확대 감각을 이어갑니다.<br>
카메라가 중심을 통과하지 않도록 최소 거리를 제한합니다.<br>
프레임 간 시간 차이를 반영해 감속하며, 테스트에서는 서로 다른 프레임 간격의 결과를 비교합니다.<br><br>

터치에서는 아이콘의 이름을 먼저 보여주고 라벨로 소개를 엽니다.<br>
보이는 라벨의 크기를 키우지 않고 터치 영역을 넓혔습니다.<br>
장식용 링과 별은 프로젝트 선택을 가로채지 않습니다.<br>

## 3. 직접 만든 형상을 반복하고, 반응을 격리하기

프로젝트 9종, 채널 2종, 종이비행기 1종의 모델을 코드로 구성했습니다.<br>
토마토·teum·픽셀 로고는 브랜드 윤곽을 살리고, 센서·서버·워치·냄비·결제 단말기는 각 작업을 상징하는 사물로 표현했습니다.<br>
외부 GLB·USDZ 파일이나 원격 모델 로더를 사용하는 구조는 아닙니다.<br><br>

같은 모델의 복제본은 기본 geometry와 material을 공유합니다.<br>
이는 `InstancedMesh`를 사용해 한 번에 그린다는 뜻은 아닙니다.<br>
호버로 개별 재질이나 형상을 바꿔야 할 때만 필요한 부분을 복제하고, 모션이 끝나면 원래 상태를 복원합니다.<br><br>

| 반응 | 실제 동작 |
|---|---|
| 공통 반응 | 회전·바운스·젤리 중 무작위 선택, 같은 아이콘에서 직전 효과의 연속 반복 방지 |
| 신호등 | 세 불빛 중 하나를 무작위로 점등 |
| 워치 | 화면·파형 밝기와 파형 높이의 작은 변화 |
| 서버 | 팬 회전 |
| 계측기 | 화면 파형 변화와 다이얼 움직임 |
| 냄비 | 김이 올라오는 반응 |
| 결제 단말기 | 카드 이동과 체크 표시 |
| 종이비행기 | 접힌 날개가 펄럭이는 반응 |

부품 반응은 여섯 기기와 비행기를 합해 7종입니다.<br>
공통 모션과 부품 모션을 함께 재생하되, 재생 중 연속 입력으로 처음부터 다시 시작하지 않습니다.<br>
모션 감소로 전환하면 움직임을 멈추고 원래 상태로 돌아갑니다.<br>

## 4. 화면 구성과 렌더링 비용을 따로 다루기

고정 시드와 구형 배치 계산으로 새로고침해도 같은 구성을 재현합니다.<br>
첫 화면에 보이는 주요 아이콘은 따로 유지하고, 나머지를 깊이가 다른 위치에 분산합니다.<br>
채널 아이콘 비율을 바꿀 때도 기존 위치와 전체 개수를 유지하도록 검사했습니다.<br><br>

초기 화면 폭에 따라 메인 오브젝트는 315개 또는 200개로 생성합니다.<br>
배경 별은 별도의 Points이며 432개 또는 288개를 표시합니다.<br>
전경의 입체 별 장식과 배경의 작은 별을 같은 항목으로 세지 않습니다.<br><br>

| 항목 | 641px 이상 | 640px 이하 |
|---|---:|---:|
| 프로젝트·채널 아이콘 | 242 | 154 |
| 종이비행기 | 24 | 15 |
| 장식 오브젝트 · 링과 별 | 49 | 31 |
| **위 세 항목 합계** | **315** | **200** |
| 배경 별 · 별도의 Points | 432 | 288 |
| pixel ratio 상한 | 1.75 | 1.5 |

오브젝트 개수는 초기 화면 폭으로 결정합니다.<br>
리사이즈하면 위치·시야각·픽셀 비율과 배경 별 표시 수를 조절하며, 기존 오브젝트 개수는 유지합니다.<br><br>

성운은 7개 위치를 갖는 셰이더 배경입니다.<br>
배경에는 카메라 이동에 따른 위치 변화를 제거해 줌할 때 전경 아이콘처럼 다가오지 않게 했습니다.<br>
실제 코드에 없는 별의 개별 반짝임이나 성운의 독립 회전을 기능으로 설명하지 않습니다.<br><br>

탭 비노출·카드나 메뉴 열림에서는 메인 renderer의 그리기를 생략합니다.<br>
사용자가 멈춤을 선택한 상태에서도 화면 변화가 필요할 때만 그립니다.<br>
이 분기보다 먼저 다음 `requestAnimationFrame`을 예약하므로, 프레임 콜백 예약까지 완전히 중단하는 방식은 아닙니다.<br><br>

실제 GPU draw call, 프레임률, 발열을 측정한 전후 기록은 없습니다.<br>
구성 수치와 코드의 자원 관리 전략을 설명하고, 성능 개선의 측정 결과로 확대하지 않습니다.<br>

## 5. 음악을 화면 전환에 맞춰 이어가기

인트로 `first-light.mp3`는 10초, 메인 `orbit.mp3`는 64초 루프입니다.<br>
CC0 악기 녹음 샘플을 이용해 사이트에 맞게 편곡한 음원이며, 직접 녹음한 악기라고 표현하지 않습니다.<br><br>

일반 인트로 시작 5초 뒤 메인 음악을 겹쳐 재생하고 3.4초 동안 음량을 올립니다.<br>
약 6.4초에 화면이 바뀌어도 같은 음원 소스와 볼륨 변화가 이어집니다.<br>
정적 인트로에서는 메인 음악을 즉시 2초 페이드인합니다.<br><br>

탭이 숨겨지면 재생과 진행 시간을 멈추고, 복귀 시 해당 위치에서 재개합니다.<br>
음소거 이후 완료된 준비 요청은 버전 확인으로 무시합니다.<br>
카드·메뉴가 열리면 소리 조절 버튼을 숨기지만, 음악 자체는 계속 이어집니다.<br>
입장·3D 조작·소개 읽기는 음원 로딩이나 재생 성공에 의존하지 않습니다.<br>

## 6. 닫힘 전환이 끝난 뒤 배경을 재개하기

프로젝트·채널·연락은 하나의 `dialog` 안에서 표시할 글을 바꿉니다.<br>
토마토 이동 메뉴는 별도 `dialog`입니다.<br>
둘 중 하나가 열리면 메인 공간의 입력과 렌더링을 중지하고, 닫을 때는 CSS 전환 완료를 기다립니다.<br><br>

이전에는 닫힘 처리와 3D 재개가 겹칠 수 있었습니다.<br>
현재는 `getAnimations()`로 닫힘 전환을 기다린 뒤, 다른 카드가 열리지 않았는지 다시 확인합니다.<br>
`closeSequence`로 오래된 닫힘 콜백이 새 상태를 덮지 못하게 하고, 마지막에 이전 초점을 복원합니다.<br>
닫힘 애니메이션과 배경 블러, 3D 렌더링이 함께 수행되는 구간을 줄이려는 변경이며, FPS 개선율을 측정한 것은 아닙니다.<br>

## 7. 연락 내용은 결과가 확인된 뒤에만 지우기

이름은 선택이며 60자, 이메일은 필수이며 254자, 내용은 필수이며 2,000자 제한을 둡니다.<br>
공백과 이메일 형식을 확인한 뒤 표준 `fetch`로 EmailJS에 요청하고 15초 시간 제한을 적용합니다.<br>
자체 서버나 자체 DB에 연락 내용을 저장하지 않습니다.<br><br>

요청 중에는 입력을 잠그고 중복 전송을 막습니다.<br>
실패하면 입력을 보존하며 자동으로 재전송하지 않습니다.<br>
카드를 닫았다 열어도 같은 DOM의 초안은 남고, 내용이 있는 상태에서 페이지를 떠나면 브라우저 기본 확인을 사용합니다.<br>
초안은 영구 저장되지 않으므로 새로고침 후 복구되는 기능은 아닙니다.<br><br>

성공 응답 뒤에는 폼을 초기화하고 3.4초의 비행 연출을 시작합니다.<br>
평면 비행기가 메인 공간과 같은 형상의 3D 모델로 전환됩니다.<br>
닫기·리사이즈·탭 비노출로 연출을 중단할 때는 시각 자원만 정리하며 성공 상태를 뒤집지 않습니다.<br>
모션 감소·3D 실패에서는 정적인 피드백을 유지하고, 상태 문장은 화면 읽기 도구에도 전달합니다.<br><br>

성공은 EmailJS의 HTTP 응답 기준입니다.<br>
사용자의 수신함 도착, 스팸 분류, EmailJS 계정의 도메인 제한은 이번 로컬 검증으로 확인하지 않았습니다.<br>

## 8. 실패해도 프로젝트를 읽을 수 있게 하기

JavaScript가 꺼져 있으면 HTML의 외부 링크를 이용할 수 있습니다.<br>
초기 스크립트가 준비되지 않으면 안전 시간 이후 입장 화면을 걷어내며, 늦게 도착해도 다시 덮지 않습니다.<br>
WebGL 초기화나 context가 실패하면 안내와 프로젝트·채널·연락 접근 경로를 보여줍니다.<br><br>

모션 감소 설정, 키보드 조작, 초점 복원, 라벨과 상태 안내를 코드와 테스트에서 다룹니다.<br>
이는 보조 기술 전반의 접근성 감사를 완료했다는 의미는 아닙니다.<br>
검증 환경과 남은 범위는 [검증 기록](VALIDATION.md)에 구분했습니다.<br>
